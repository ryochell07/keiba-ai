# 日常運用マニュアル

## 毎朝

スマホでダッシュボードを開くだけです。

| タブ | 確認できること |
|---|---|
| 今日 | 開催一覧、期待値上位、注目レース |
| レース | 全レース一覧。タップで出走馬と券種別ランキング |
| ランキング | 期待値、券種別、レース別、AI確率、人気との乖離 |
| 分析 | 回収率、確率の精度、新旧モデルの比較 |
| モデル | 手法別の精度、市場との比較、期待値別の実績、実験の記録 |
| 状態 | データの最新日、取得エラー、モデルの版 |

### 表示の読み方

- **期待値 +20%**: 推定確率×オッズが1.2。推定が正しければ、長期的に1.2倍戻る計算です
- **オッズ未取得**: 発売前か取得前です。期待値は計算しません
- **信頼度 A/B/C**: 確率のばらつき、過去走数、確率の低さから判定します
- **確率**: オッズ取得後はAIと単勝オッズの合成です。市場の評価が大部分を占めます。中央は、オッズが揃うとAIを使わず単勝オッズだけで出します
- **長期回収率は未検証**: 発走前オッズでの十分な実績がまだありません。多くの買い目に付きます
- **同条件の過去回収率 52%**: 同じ券種で期待値プラスと判定した買い目の、バックテストでの回収率です。**100%を下回るなら、その期待値プラスは当てになりません**
- **複勝・ワイドの 〜**: オッズの幅に対応する下限と上限です

AI確率は確定前の推定です。朝の時点は馬体重や馬場が未確定で、発走が近いほど情報が増えます。

## 自動で動くもの

| いつ (JST) | 内容 |
|---|---|
| 毎日 6:00 | 中央・地方の確定結果の取得、予測との照合、出馬表更新、予測、ページ更新 |
| 毎日 9:00-21:30 の30分ごと | 地方の当日データ、土日月は中央の出馬表とオッズを取得し、期待値を更新 |
| 毎月第1月曜の朝 | 再学習とバックテスト。旧モデルより悪ければ採用しません |
| 毎晩 22:00 | 過去データの続きを取得 (2024年1月まで完了すると短時間で終わります) |
| データが1.3倍以上に増えた朝 | 自動で再学習。3000レース未満の初期段階は比較なしで更新します |

GitHubの定期実行は混雑で遅れることがあります。発走直前の値は保証されません。

## ときどき行うこと

現在のモデルを確認します。

```bash
.venv/bin/keiba models
```

モデルを1つ前に戻します。

```bash
.venv/bin/keiba rollback --org JRA
```

過去データを増やすときは、Actionsの `backfill` を期間と取得元を指定して手動実行します。切れても再実行で続きから進みます。

### 手動の再学習

Actionsの `retrain` を手動実行します。定期実行はしません。

| task | 内容 |
|---|---|
| `backtest` | 合成係数 (α、β) を推定し直します |
| `train` | 再学習して採用します。`force` を付けると旧モデルとの比較をせずに採用します |
| `rollback` | 直前に採用していたモデルへ戻します。もう一度実行すると元に戻ります |

- 合成係数は学習時に版へ記録するので、`backtest` → `train` の順に、主催ごとに実行します
- `save` を付けない実行は、所要時間と動作の確認だけで何も保存しません。初めて動かすときはこちらで確かめます
- `save` を付けた実行は、終わるまで定期実行を待たせます。発走前オッズの取得が終わる 22:30 以降に始めます
- 新しいモデルは `config/blend_ci.yaml` に係数の信頼区間がないため、`keiba bundle` の判定は「市場単独を推奨」になります。`blend_enforce` を有効にしないかぎり、地方の予測は合成のままです

## 使ううえでの注意

バックテストの回収率が良くても、将来の利益は保証されません。「分析」の95%区間が100%をまたぐ場合は、偶然と区別できません。
馬券の購入は自己責任で、余裕資金の範囲に留めてください。

## 予測の記録と発走前オッズ

予測は発走前の分だけ追記で記録します。削除も更新もできません。

```bash
.venv/bin/keiba odds-report --date 2026-11-07
```

その日の発走前オッズの取得率を表示します。

```bash
.venv/bin/keiba replay 予測ID
```

記録した入力から確率を計算し直して、記録と比べます。

```bash
.venv/bin/keiba bundle
```

使用中のモデルの再現情報と、合成係数の判定を表示します。

`config/sources.yaml` の `guards` で、自動の再学習 (`freeze_models`) と市場単独への切り替え (`blend_enforce`) を指定します。
`market_only_orgs` に書いた主催は、判定にかかわらず、オッズが揃ったレースを市場単独で出します。AIと合成の確率も比較用に記録します。
